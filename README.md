# proxyharvest

**زبان‌ها:** [فارسی](README.md) · [English](README.en.md) · [Русский](README.ru.md) · [Español](README.es.md) · [中文](README.zh.md)

ابزار خط فرمان Go برای جمع‌آوری پروکسی‌های رایگان از رجیستری داخلی سایت‌ها (داخل کد)، تست واقعی آن‌ها از اتصال مستقیم و مرتب‌سازی بر اساس سرعت.

باینری‌های ایستا برای Linux و Windows (amd64/arm64) در صفحهٔ [Releases](https://github.com/FossilizedProgrammer/proxyharvest/releases) منتشر می‌شوند — خود گیتهاب با Actions آن‌ها را از همین سورس می‌سازد.

## ساخت

```bash
go build -o proxyharvest .
```

## استفاده

```bash
# همه سایت‌ها، همه کشورها، خروجی پیش‌فرض proxies.txt
./proxyharvest

# فقط پروکسی‌های آمریکا، ۲۰ مورد سریع‌تر
./proxyharvest -country US -top 20 -out us.txt

# فقط HTTP و SOCKS5
./proxyharvest -types http,socks5

# نشان دادن جزئیات هر منبع (موفق/ناموفق، تعداد، پروکسی‌های جایگزین)
./proxyharvest -v
```

`-country` کد دوحرفی ISO می‌گیرد (مثل `US`، `DE`، `IR`).

## پروکسی آپ‌استریم

اگر دسترسی مستقیم به سایت‌های فهرست مسدود است، با `-upstream` یک پروکسی واسط بدهید. این پروکسی **فقط** برای دانلود فهرست سایت‌ها (و استعلام کشور) استفاده می‌شود؛ مرحلهٔ تست همچنان از اتصال مستقیم انجام می‌شود و پروکسی آپ‌استریم در مسیر هیچ تستی قرار نمی‌گیرد.

```bash
# پروکسی HTTP با نام کاربری و رمز اختیاری
./proxyharvest -upstream http://user:pass@10.0.0.5:8080

# SOCKS5 و شکل کوتاه host:port (به‌طور پیش‌فرض HTTP)
./proxyharvest -upstream socks5://10.0.0.5:1080
./proxyharvest -upstream 10.0.0.5:8080
```

پروتکل‌های مجاز: `http`، `https` و `socks5` (با احراز هویت اختیاری `user:pass@`). پورت باید صریح باشد.

## بررسی دسترسی به سایت‌های واقعی

گذر از تست سرعت به‌معنای قابل‌استفاده‌بودن پروکسی در مرورگر نیست؛ خیلی از پروکسی‌های رایگان فقط یک درخواست ساده را جواب می‌دهند و تونل TLS به سایت‌های بزرگ را باز نمی‌کنند. به همین دلیل بعد از تست سرعت، هر پروکسی از طریق خودش `https://www.facebook.com` و `https://www.youtube.com` را باز می‌کند (درخواست کامل HTTPS با گواهی معتبر، مثل مرورگر) و فقط آن‌هایی که **هر دو** را باز کنند در خروجی می‌مانند. پروکسی‌هایی که ۵xx یا خطای تونل/گواهی بدهند حذف می‌شوند.

```
./proxyharvest                       # فیس‌بوک و یوتیوب، پیش‌فرض
./proxyharvest -require www.instagram.com,www.youtube.com
./proxyharvest -require none         # بدون این بررسی
```

آدرس‌ها را با کاما جدا کنید؛ اگر scheme ندهید `https://` در نظر گرفته می‌شود. با `-v` دلیل ردشدن هر پروکسی لاگ می‌شود.

> خطای `SEC_ERROR_UNKNOWN_ISSUER` در فایرفاکس برای سایت‌های HSTS یعنی پروکسی در حال رمزگشایی TLS است و گواهی جعلی نشان می‌دهد. چون HSTS اجازهٔ استثنا نمی‌دهد، تنها راه، استفاده‌نکردن از آن پروکسی است؛ بررسی `-require` همین پروکسی‌ها را به‌عنوان `TLS interception` رد می‌کند. اگر این خطا بدون پروکسی هم دیده شود، آنتی‌ویروس/فایروال یا شبکهٔ ISP در حال MITM است و به ابزار مربوط نیست.

## گزینه‌ها

| گزینه | پیش‌فرض | توضیح |
|---|---|---|
| `-country` | همه | فقط همان کشور |
| `-exclude-countries` | `IR,RU,CN,KP` | پروکسی‌های این کشورها اصلاً استفاده نشوند (`none` برای غیرفعال‌کردن) |
| `-types` | `http,socks4,socks5` | نوع پروکسی‌ها |
| `-c` | `100` | تعداد تست هم‌زمان |
| `-timeout` | `8s` | مهلت هر تست پروکسی |
| `-fetch-timeout` | `25s` | مهلت دانلود هر منبع |
| `-test-url` | `https://www.gstatic.com/generate_204` | آدرس تست سرعت (نسخه HTTP هم خودکار امتحان می‌شود) |
| `-max-per-source` | `500` | حداکثر کاندید از هر سایت |
| `-top` | `0` (همه) | نگه‌داشتن N مورد سریع‌تر |
| `-out` | `proxies.txt` | فایل خروجی |
| `-upstream` | — | پروکسی آپ‌استریم فقط برای دانلود سایت‌ها (تست پروکسی‌ها از آن عبور نمی‌کند) |
| `-no-retry` | — | سایت‌های در دسترس‌نبوده را رها کن و از پروکسی برای بازیابی‌شان استفاده نکن |
| `-require` | `www.facebook.com,www.youtube.com` | هر پروکسی باید این سایت‌ها را با HTTPS باز کند؛ `none` برای غیرفعال‌کردن |
| `-list-sources` | — | نمایش سایت‌های شناخته‌شده |

## نمایش پیشرفت

در حین اجرا یک خط وضعیت زنده روی `stdout` نمایش داده می‌شود که مرحلهٔ جاری، شمارش پیشرفت و زمان سپری‌شده را نشان می‌دهد؛ پس اگر کار طول بکشد کاملاً مشخص است که ابزار مشغول است و هنگ نکرده:

```
| downloading source lists: 7/11 requests, 2015 candidates [6s]
```

مراحل به این ترتیب نمایش داده می‌شوند: `downloading source lists` → `checking harvested proxies` → `recovering unreachable sources` → `resolving proxy countries` → `testing proxies`. اگر خروجی را به فایل هدایت کنید، همین خطوط هر چند ثانیه به `stderr` می‌روند تا `stdout` تمیز بماند.

## ساخت و رلیز

پیش‌نیاز: Go 1.27+. وابستگی‌ها حداقلی‌اند (فقط `golang.org/x/net`) و مستقیم دانلود می‌شوند:

```bash
./build.sh          # هر چهار هدف: linux/amd64+arm64, windows/amd64+arm64
# یا دستی:
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o proxyharvest .
```

باینری‌ها ایستا و بدون وابستگی اجرایی‌اند. رلیزها با push کردن تگ `v*` به‌صورت خودکار توسط GitHub Actions ساخته و منتشر می‌شوند.

## نحوهٔ کار

1. دامنه‌ها از **رجیستری داخلی در کد** خوانده می‌شوند — فایل خارجی لازم نیست.
2. همهٔ منابع به‌طور مستقیم (یا از طریق `-upstream` در صورت تنظیم) و هم‌زمان دانلود می‌شوند. هر منبعی که در دسترس نباشد، با پروکسی‌های سالمِ جمع‌آوری‌شده از منابع دیگر دوباره امتحان می‌شود؛ با `-no-retry` این مرحله انجام نمی‌شود و ابزار فقط با سایت‌های در دسترس کار می‌کند.
3. پروکسی‌ها یک‌بار و از **اتصال مستقیم** تست می‌شوند (هیچ پروکسی واسطی در تست دخالت ندارد)؛ فقط اتصال از طریق خود پروکسیِ تحت تست برقرار می‌شود.
4. پروکسی‌های مرده یا غیرقابل‌دسترس به‌طور کامل حذف می‌شوند.
5. برای پروکسی‌هایی که کشورشان از منبع مشخص نیست، کشور از `ip-api.com` گرفته می‌شود. سپس فیلتر `-country` (فقط یک کشور) و لیست سیاه `-exclude-countries` (پیش‌فرض ایران، روسیه، چین و کرهٔ شمالی) روی آن اعمال می‌شود؛ پروکسی‌های کشورهای لیست سیاه حتی اگر از تست‌ها رد شوند، در خروجی نمی‌آیند.

```
./proxyharvest                                  # حذف IR, RU, CN, KP (پیش‌فرض)
./proxyharvest -exclude-countries IR,CN
./proxyharvest -exclude-countries none          # همهٔ کشورها مجاز
```
6. خروجی بر اساس تأخیر اندازه‌گیری‌شده (صعودی) مرتب می‌شود.
