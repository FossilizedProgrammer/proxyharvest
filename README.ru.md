# proxyharvest

**Языки:** [فارسی](README.md) · [English](README.en.md) · [Русский](README.ru.md) · [Español](README.es.md) · [中文](README.zh.md)

Консольный инструмент на Go для сбора бесплатных прокси из встроенного в код реестра сайтов, их реальной проверки с прямого соединения и сортировки по скорости.

Статические бинарники для Linux и Windows (amd64/arm64) публикуются на странице [Releases](https://github.com/FossilizedProgrammer/proxyharvest/releases) — их собирает сам GitHub через Actions из этого же исходника.

## Сборка

Требование: Go 1.27+. Зависимость минимальная (`golang.org/x/net`) и скачивается напрямую:

```bash
./build.sh          # все четыре цели: linux/amd64+arm64, windows/amd64+arm64
# или вручную:
CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o proxyharvest .
```

Бинарники статические и не требуют ничего при запуске. Релизы публикуются автоматически через GitHub Actions при push тега `v*`.

## Использование

```bash
# все сайты, все страны, вывод в proxies.txt по умолчанию
./proxyharvest

# только американские прокси, 20 самых быстрых
./proxyharvest -country US -top 20 -out us.txt

# только HTTP и SOCKS5
./proxyharvest -types http,socks5

# показать детали по каждому источнику (успех/неудача, количество, запасные)
./proxyharvest -v
```

`-country` принимает двухбуквенный ISO-код (например `US`, `DE`, `IR`).

## Просмотр и выбор сайтов

У каждого сайта есть короткое имя. Посмотреть все сайты и точные адреса загрузки:

```bash
./proxyharvest -list-sources
```

Используйте `-sources`, чтобы собирать прокси только с выбранных сайтов (через запятую):

```bash
# только два сайта
./proxyharvest -sources spys.me,geonode.com

# все, кроме одного (префикс ! или -)
./proxyharvest -sources '!spys.me'

# только SOCKS5 с одного сайта
./proxyharvest -sources spys.me -types socks5
```

Неизвестное имя даёт ошибку с напоминанием о `-list-sources`. В логе видно, сколько сайтов выбрано:

```
proxyharvest: collecting proxies from 2 of 11 sites: spys.me, geonode.com (country=all, types=http)
```

## Upstream-прокси

Если прямой доступ к сайтам из списка заблокирован, передайте промежуточный прокси через `-upstream`. Он используется **только** для скачивания списков сайтов (и запроса страны); этап тестирования всегда идёт с прямого соединения, и upstream-прокси не участвует ни в одном тесте.

```bash
# HTTP-прокси с опциональным логином/паролем
./proxyharvest -upstream http://user:pass@10.0.0.5:8080

# SOCKS5 и краткая форма host:port (по умолчанию HTTP)
./proxyharvest -upstream socks5://10.0.0.5:1080
./proxyharvest -upstream 10.0.0.5:1080
```

Поддерживаемые схемы: `http`, `https` и `socks5` (с опциональной аутентификацией `user:pass@`). Порт должен быть указан явно.

## Проверка реальной доступности сайтов

Прохождение теста скорости ещё не значит, что прокси годится для браузера: многие бесплатные прокси отвечают на простой запрос, но не пропускают TLS-туннель к крупным сайтам. Поэтому после теста скорости каждый прокси через себя открывает `https://www.facebook.com` и `https://www.youtube.com` (полный HTTPS-запрос с валидным сертификатом, как браузер), и в выводе остаются только те, что открыли **оба**. Прокси, отвечающие 5xx или ошибкой туннеля/сертификата, отбрасываются.

```
./proxyharvest                       # Facebook и YouTube, по умолчанию
./proxyharvest -require www.instagram.com,www.youtube.com
./proxyharvest -require none         # без этой проверки
```

Адреса разделяются запятыми; без схемы считается `https://`. С `-v` в журнале видна причина отказа каждого прокси.

> Ошибка `SEC_ERROR_UNKNOWN_ISSUER` в Firefox для HSTS-сайтов означает, что прокси расшифровывает TLS и показывает подделный сертификат. HSTS не допускает исключений, поэтому единственный выход — не пользоваться таким прокси; проверка `-require` отбраковывает их как `TLS interception`. Если ошибка видна и без прокси — MITM делает антивирус/файрвол или сеть провайдера, к инструменту это отношения не имеет.

## Опции

| Флаг | По умолчанию | Значение |
|---|---|---|
| `-country` | все | только эта страна |
| `-exclude-countries` | `IR,RU,CN,KP` | прокси этих стран вообще не используются (`none` — отключить) |
| `-types` | `http,socks4,socks5` | типы прокси |
| `-c` | `100` | параллельных тестов |
| `-timeout` | `8s` | таймаут каждого теста прокси |
| `-fetch-timeout` | `25s` | таймаут скачивания каждого источника |
| `-test-url` | `https://www.gstatic.com/generate_204` | URL теста скорости (HTTP-версия тоже пробуется автоматически) |
| `-max-per-source` | `500` | максимум кандидатов с одного сайта |
| `-top` | `0` (все) | оставить N самых быстрых |
| `-out` | `proxies.txt` | файл вывода |
| `-upstream` | — | upstream-прокси только для скачивания сайтов (тесты через него не идут) |
| `-no-retry` | — | бросить недоступные сайты и не восстанавливать их через собранные прокси |
| `-require` | `www.facebook.com,www.youtube.com` | каждый прокси должен открыть эти сайты по HTTPS; `none` — отключить |
| `-sources` | все | собирать только с этих сайтов (имена из `-list-sources`); `!name` — исключить сайт |
| `-list-sources` | — | показать известные сайты и их адреса |

## Отображение прогресса

Во время работы на `stdout` идёт живая строка статуса с текущим этапом, счётчиком и прошедшим временем — если работа затянулась, видно, что инструмент занят, а не завис:

```
| downloading source lists: 7/11 requests, 2015 candidates [6s]
```

Этапы: `downloading source lists` → `checking harvested proxies` → `recovering unreachable sources` → `resolving proxy countries` → `testing proxies`. При перенаправлении вывода в файл эти строки раз в несколько секунд уходят в `stderr`, чтобы `stdout` оставался чистым.

## Как это работает

1. Домены берутся из **реестра внутри кода** — внешний файл не нужен.
2. Все источники скачиваются одновременно — напрямую (или через `-upstream`, если задан). Недоступный источник повторно пробуется через рабочие прокси, собранные из других источников; с `-no-retry` этот шаг пропускается.
3. Прокси тестируются **с прямого соединения** (никакой промежуточный прокси в тест не вмешивается); соединение идёт только через сам проверяемый прокси.
4. Мёртвые и недоступные прокси полностью отбрасываются.
5. Для прокси, чья страна не ясна из источника, страна запрашивается у `ip-api.com`. Затем применяется фильтр `-country` (одна страна) и чёрный список `-exclude-countries` (по умолчанию Иран, Россия, Китай и Северная Корея); прокси из чёрного списка не попадают в вывод, даже если прошли тесты.

```
./proxyharvest                                  # убрать IR, RU, CN, KP (по умолчанию)
./proxyharvest -exclude-countries IR,CN
./proxyharvest -exclude-countries none          # разрешить все страны
```
6. Вывод сортируется по измеренной задержке (по возрастанию).

## Формат вывода

```
# columns: proxy_url	country	latency_ms	source
http://1.2.3.4:8080	US	210	freeproxyhub.net
socks5://5.6.7.8:1080	DE	540	spys.me
```

Бесплатные прокси нестабильны и могут умереть через несколько минут. Ответственность за их использование — на вас.
